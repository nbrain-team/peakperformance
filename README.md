## What this is

A 100% self-contained static copy of the live Peak Property Performance® site,
generated by `scripts/static-export/build-html-mirror.mjs`. It's intended for
evaluating a move off the current Next.js + Payload CMS stack onto plain
static HTML hosting.

Every URL reference inside the mirror is **relative**, so it works equally
well two ways:

1. **Double-click `index.html`** in Finder. The browser opens it via
   `file://` and every link, image, font, and stylesheet resolves
   correctly against the filesystem.
2. **Run an HTTP server** for a closer-to-production preview:
   ```
   npm run html:preview      # python3 -m http.server 4321 --directory peak-html
   ```
   then open <http://localhost:4321>.

## How to regenerate

```
npm run html:build
```

This wipes `peak-html/` and re-crawls the live deployment from scratch.
Re-run any time the live site changes — the mirror does not auto-update.

## What stays remote

To keep the mirror lean and to avoid breaking anything that legitimately
needs a live network call, the following hosts are **not** downloaded —
they keep loading from the network:

- `fonts.googleapis.com`
- `fonts.gstatic.com`
- `www.googletagmanager.com`
- `www.google-analytics.com`
- `use.typekit.net`

## Known limitations of going static

- **Embedded forms** (PPP Review request, Be On The Show, Starter Kit) all
  POST to live API routes (`/api/ppp-review`, `/api/starter-kit`). On a
  pure static host these routes do not exist — the form will need to
  re-target a third-party form provider (e.g. HubSpot, Formspree, Pardot).
  If the new provider's CORS allowlist isn't updated for the new host,
  embedded forms will fail to load their schema.
- **Payload admin disappears.** `/admin` and `/api/*` routes are not
  exported. All content edits would need to be made by re-running the
  build against an updated source.
- **Sitemap, robots.txt, RSS feed will go stale** unless regenerated. The
  live site does not currently expose a `/sitemap.xml` — if you migrate
  to a static host, generate a sitemap from the file tree as part of the
  build.
- **Live preview, draft mode, on-demand revalidation** all stop working —
  these depend on Payload + Next.js running server-side.
- **Image optimization** (`/_next/image`) is gone. The mirror points
  every reference at the underlying source image at full resolution.
- **Analytics tracking** still loads (Google Tag Manager) but tracking
  beacons may not fire from the `file://` protocol due to CORS.
