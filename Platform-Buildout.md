# Platform Buildout — Peak Property Performance® (peakpropertyperformance.com)

Living knowledge base for the PPP web platform. Update this file whenever the architecture, integrations, or deployment context changes.

## Repository: `nbrain-team/peakperformance`

This GitHub repo (`nbrain-team/peakperformance`) is a **static HTML mirror** of the live production site at https://www.peakpropertyperformance.com. It is auto-generated by `scripts/static-export/build-html-mirror.mjs` (the script lives in the source Next.js repo, not here). The mirror is intended as the deliverable for moving off the existing Next.js + Payload CMS stack onto plain static HTML hosting.

**Important consequence:** Edits made directly inside this repo are the authoritative copy until the source Next.js repo is also updated and re-mirrored. If the live site is regenerated, hand edits here will be overwritten unless they are also applied upstream.

### Hydration / Next.js notes

Each HTML page is a fully rendered server snapshot **plus** a set of `self.__next_f.push([1, "..."])` data-flight scripts that re-hydrate the page client-side using `_next/static/chunks/...`. When you hand-edit a section's HTML, you must also update the matching flight payload in the same file (the same JSON-ish blob describing the section), otherwise React will replace the section with the original markup on hydration.

The chunk that holds the page body content is normally `8:[false,[[section1],[section2],...]]`. The footer is usually chunk `6`, nav is chunk `4`.

## Production site (peakpropertyperformance.com)

- **Stack:** Next.js (App Router) + Payload CMS + Fast Company Press content.
- **Form backends in source:** `POST /api/ppp-review` (PPP Review form), `POST /api/starter-kit` (Starter Kit email capture). These routes exist in the live deployment but do NOT exist in this static mirror.

## Deployment

The static mirror can be hosted from any static file server (S3 + CloudFront, Netlify, Vercel static, GitHub Pages, etc.). No build step required to serve.

**Known limitations of going pure-static** (from `README.md`):
- All `/api/*` routes are gone — forms must use a third-party provider.
- Payload admin (`/admin`) is gone.
- Sitemap, robots.txt, RSS need to be regenerated from the file tree.
- Live preview / draft mode / on-demand revalidation no longer work.
- `/_next/image` optimization is gone; images served at full resolution.
- GA still loads but beacons may be blocked on `file://`.
